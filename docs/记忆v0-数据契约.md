## 一、四个追加日志（JSONL：一行一个 JSON 对象，只追加、不改写）

所有文件首行不写注释（JSONL 必须每行可解析）。字段缺失时**省略该字段**，不要写 null。

### 1. `events.jsonl` —— 发生了什么（v0 唯一自动写入的文件）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| schemaVersion | number | 是 | 固定 `1` |
| id | string | 是 | `evt_<yyyymmdd>_<6位序号>`，进程内递增 |
| at | string | 是 | ISO 本地时间，例 `2026-11-12T14:30:05+08:00` |
| kind | string | 是 | `message` / `diary` / `learning` / `action` / `milestone` |
| platform | string | 是 | `qq` / `bilibili` / `wechat` / `local` |
| who | string | 是 | `主人` / `群 <群号>` / `她` |
| summary | string | 是 | 一句话，≤ 120 字 |
| perms | string | 是 | `private`（私聊/只给自己）/ `shared`（群里）/ `system` |
| ref | string | 否 | 关联 id：会话段 id、日记文件相对路径、消息 message_id |

### 2. `memories.jsonl` —— 记住了什么（v0 只读，由以后的学习/反思流程写入）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| schemaVersion | number | 是 | `1` |
| id | string | 是 | `mem_<yyyymmdd>_<6位>` |
| at | string | 是 | 同 events.at |
| type | string | 是 | `episodic` / `person` / `knowledge` / `skill` / `self` |
| content | string | 是 | 记忆正文，≤ 200 字 |
| sourceEvent | string | 否 | 对应 events.id |
| confidence | number | 否 | 0–1 |
| visibility | string | 是 | `private` / `shared` / `public` |

### 3. `skills.jsonl` —— 会了什么（v0 只读）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| schemaVersion | number | 是 | `1` |
| id | string | 是 | `skl_<yyyymmdd>_<6位>` |
| at | string | 是 | — |
| skill | string | 是 | 技能名，例 `Unity 2D 动画` |
| level | string | 是 | `了解` / `理解` / `掌握` / `熟练` |
| evidence | string[] | 否 | events.id 列表 |
| note | string | 否 | ≤ 120 字 |

### 4. `personality.jsonl` —— 她变成什么样了（v0 只读）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| schemaVersion | number | 是 | `1` |
| id | string | 是 | `per_<yyyymmdd>_<6位>` |
| at | string | 是 | — |
| kind | string | 是 | `sample`（一次观察）/ `change`（一次正式变更） |
| traits | object | 是 | 五个维度，0–1 小数：`initiative`（主动）/ `curiosity`（好奇）/ `humor`（幽默）/ `clinging`（黏人）/ `tsundere`（嘴硬） |
| why | string | 否 | 为什么这样判断，≤ 120 字 |
| evidence | string[] | 否 | events.id 列表 |

> **样本不够就不画**：`sample` 少于 3 条时，人格页显示「还没有采样，画了也是假数据」。

## 二、写入点（v0 只写 events.jsonl，且必须 fail-soft）

| 时机 | kind | platform | who | perms | summary |
|---|---|---|---|---|---|
| QQ 消息**成功投递给她**之后 | `message` | `qq` | 私聊=`主人`，群=`群 <群号>` | 私聊 `private`，群 `shared` | 消息正文前 120 字（去掉 CQ 码） |
| 每天早上首次消息下发日记任务时 | `diary` | `local` | `她` | `system` | `按新格式写今天的两篇日记` |
| `POST /lanyuxi/diary/write` 触发时 | `diary` | `local` | `她` | `system` | `面板让她补写今天的日记` |

> **fail-soft 是硬要求**：写日志失败只能记 `diag.memoryError`，绝不能让消息投递或日记流程抛错。

## 三、只读接口 `GET /lanyuxi/growth`

查询参数：`limit`（默认 50，上限 200）、`kind`（可选，过滤 events）。

响应（字段名固定，前端按此渲染）：

```json
{
  "ok": true,
  "generatedAt": "2026-11-12T14:30:05+08:00",
  "counts": { "events": 0, "memories": 0, "skills": 0, "personalitySamples": 0 },
  "timeline": [
    { "at": "2026-11-12T14:30:05+08:00", "kind": "message", "platform": "qq",
      "who": "主人", "summary": "在吗", "perms": "private", "ref": "lanyuxi-msg2-002" }
  ],
  "personality": {
    "latest": null,
    "latestAt": null,
    "traits": { "initiative": null, "curiosity": null, "humor": null, "clinging": null, "tsundere": null },
    "samples": 0,
    "history": [ { "at": "...", "kind": "change", "why": "…" } ],
    "card": { "path": "lanyuxi-home/persona/人格卡.md", "exists": true, "bytes": 3586, "head": "前 300 字" }
  },
  "files": { "dir": "E:\\dsh-foundry\\lanyuxi-home\\memory", "exists": true }
}
```

约定：
- 文件不存在 → `counts` 全 0、`timeline` 空数组、`personality.latest = null`，**不要报错**（HTTP 200）。
- `timeline` 按 `at` 倒序；坏行（解析失败的 JSON）跳过，并在 `skipped` 里给个计数（可选字段）。
- 只读：该接口**不写任何文件**。

## 四、明确不做（附触发条件）

| 项 | 什么时候才做 |
|---|---|
| SQLite / PostgreSQL / pgvector | `events.jsonl` 超过 5 万行，或关键词检索明显变慢，或要做语义回忆 |
| 向量检索 | 需要「她按意思想起相关的事」时 |
| Python Worker | 要视频理解 / PDF 批量解析 / 本地 Embedding 时 |
| LoRA 微调 | 不作为基础设施；等上述都稳定、有几千条高质量样本再评估 |
